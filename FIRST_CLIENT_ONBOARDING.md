# First restaurant onboarding

KitchenOps est installable sans caméra fixe.

## Données à récupérer auprès du chef

### Produits
Pour chaque référence réellement utile :
- nom utilisé en cuisine ;
- catégorie ;
- unité de travail : kg, L, pièce, bac, carton ;
- stock de départ ;
- niveau cible à avoir avant une commande ;
- coût unitaire approximatif si disponible.

Commencer par 30 à 60 références importantes au lieu de saisir toute la cuisine.

### Recettes autorisées
Trois groupes séparés :
- CARTE ;
- PLAT_DU_JOUR ;
- PERSONNEL.

Pour chaque recette :
- nom ;
- nombre de portions de référence ;
- quantité de chaque ingrédient par portion ;
- notes/allergènes éventuels.

KitchenOps ne propose aucune recette hors de ces listes.

### Documents fournisseur
Récupérer 5 à 10 exemples récents :
- bons de commande ;
- bons de livraison ;
- factures si elles sont utilisées pour contrôler les réceptions.

Ces exemples servent à mesurer la qualité d'extraction photo.

## Installation physique minimale

- tablette existante ou appareil Android/iPad avec navigateur récent ;
- Wi-Fi stable dans ou près de la réserve ;
- aucun perçage et aucune caméra fixe au pilote initial ;
- photos prises à la demande.

## Protocole pilote 30 jours

Semaine 1 :
- configuration des références et recettes ;
- contrôle systématique des extractions ;
- aucune application automatique sans validation du chef.

Semaines 2 à 4 :
- photo des documents fournisseur ;
- photo chambre froide une fois par jour ou avant préparation des commandes ;
- suivi des suggestions de réassort ;
- suivi du temps gagné.

## Mesures à conserver

- minutes nécessaires pour préparer une commande avant/après ;
- ruptures de stock ;
- achats d'urgence ;
- produits surstockés ;
- écarts entre photo et inventaire réel ;
- nombre d'extractions IA corrigées ;
- économies ou pertes évitées quand elles sont mesurables.

Le succès du pilote doit être décidé sur ces mesures, pas sur l'impression que l'IA est intéressante.
